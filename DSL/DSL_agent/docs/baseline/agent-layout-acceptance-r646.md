八个模型为 32 元素平方、65 元素尾块平方，以及六个外部状态权重模型：MLP、Conv→Pool、残差、BatchNorm 多输出、矩阵融合、形状→Linear。尾块、BatchNorm 和矩阵融合另做新输入执行。六个状态模型使用固定外部随机权重。

本批全部为规则候选，数值门限保持 `1e-5 + 1e-4*abs(reference)`。新输入分别通过数学解释器与 CPU float64 Torch 参考，再比较真实解密结果。程序包执行端仅接收评估密钥；重载和新输入执行均为 0 次生成、0 次编译。

## 布局与接口

策略 `bound-layouts-v1` 默认最多准备 8 个候选、限时 120 秒，硬上限 180 秒。使用现有平台、资源与编译配置；显式周期、packing 或构造要求保留。排序依据为输入输出物理声明数、公开常量条目、公共元素数及周期。

| 模型 | 原布局声明数 | 选择后声明数 | 周期 |
|---|---:|---:|---:|
| 32 元素平方 | 16 | 2 | 32 |
| 65 元素尾块平方 | 18 | 2 | 128 |
| Conv→Pool | 3 | 2 | 8 |

数量为物理输入输出声明之和，包含辅助输入。该排序只提供确定性初始选择；更大周期可能增加公开常量，实际耗时和内存没有作性能结论。峰值内存、执行时间、乘法深度与中间密文仍记为 unknown，编译和密态可行性分别验收。

`plan_model()` 返回计划、拒绝项、资源与源码绑定；`check_plan()` 核验选定请求；`submit_planned()` 显式委托现有 `Application.submit()`。任务预算、取消、生成、修复和交付沿用原控制层。宿主保存布局计划，程序包绑定选定的请求与布局。旧 submit 与 CLI 默认行为保持。

使用命令：

~~~bash
python3 -B scripts/plan_model.py --case model.json --output layout-plan.json
~~~

组件用法见[应用接口](application-agent-component-v1.md#布局准备)。
