## 原因与下一方向

延后槽位整理解决了原来最先遇到的一处乘法容量问题，但下一处 `earth.mul` 仍包含 `ci<90 * 11>` 与 `pl<45 * 11>`：预期乘积 scale 为 135 位，剩余两个数据模数容量约 120 位。原 150 位乘法错误和新错误均保留。首次错误位置改变，不算编译成功。

带补零的视图包含零边界与不同索引对，延后整理需要分别计算多项式。展开工作量为 1063–1623，超过当前 1024 上限。内联临时量保持相同算术图，因此工作量不变。独立明文比较最大绝对误差 1.66534e-16，仅证明有限测试上的表达一致。

后续可继续研究降低深层多项式计算深度或共享计算的等价写法；当前结果没有证明这些模型不可表达。编译调度或参数方案涉及新的批准边界；真实 bootstrap 的精度问题仍需单独解决。
