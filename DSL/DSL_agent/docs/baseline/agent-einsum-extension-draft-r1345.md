# Einsum 对角与标量分解：开发版验收

开发版增加重复标签的对角提取、trace 和标量 Tensor 因子，
复用当前 reshape、公开索引 gather、matmul、乘法和归约。
生产 PyTorch 入口仍为 v18，新增来源语法尚未激活。

## 结果

| 范围 | 通过 | 失败／错误／跳过 |
|---|---:|---:|
| 形状、分解、参考和拒绝测试 | 49 | 0／0／0 |
| 存储别名及双向写入检查 | 13 | 0／0／0 |
| Poseidon CPU 规则模型 | 9 | 0／0／0 |

数学差分包含 21 个不同方程/形状上下文，各使用四组输入，对照原生
Torch einsum 和现有独立数学解释器。别名检查区分直接视图与计算所得张量。

九模型完成真实 frontend tracing、Earth/CKKS 编译、RuntimePlan、
OperatorSpec、bundle 检查、Poseidon CPU 密态、最终解密与数值比较，
以及程序包重载后的新输入执行：9 次编译、18 次密态调用、
72 组输入、144 个输出值，最大绝对误差 `8.694419628696437e-9`。

| 分区 | 三个实际上下文 |
|---|---|
| 对角提取 | 矩阵对角、批次对角、对角接矩阵融合 |
| trace | 标量 trace、批次 trace、trace 乘标量 |
| 标量因子 | 标量乘矩阵、向量归约乘标量、三个标量连乘 |

冻结门限仍为 `1e-5 + 1e-4*abs(reference)`。
这些是规则候选的后端验收；本轮没有真实 Agent 生成或新 PyTorch 来源捕获。

## 修复与记录

首轮工具漏传两个必填预算字段，九任务在输入检查拒绝，编译和密态调用为零。
修正后，三个标量组合通过；六个对角/trace 模型的规则准备发现默认布局 v8
缺少静态索引绑定。按正常选项显式选择已有 v9，六项补验通过。
没有重跑已通过的三项，三个批次沿用同一原始截止时间。旧任务、失败及绑定保留。

开发版记录原方程、逻辑形状、分解节点、公开索引、来源映射和哈希。
重复标签在同一操作数内要求维度完全相等；各操作数之间按合法广播规则处理。
逻辑标量使用 `[1]` 密文载体并明确保留 `[]` 数学形状。
这不代表当前生产入口已接受 rank-0 输入或标量视图写入。
