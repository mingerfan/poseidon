# 完整 PyTorch 来源接入：v36 阶段结果

已完成显式 v36 来源记录接入。两个较大来源模型通过了应用入口、真实 Poseidon CPU 编译和数值验收，并完成程序包重载、新输入、重复执行及缓存复用。

## 改动

- 完整来源记录按重复容器无损存储，保存声明顺序和内容哈希。
- 来源捕获、应用任务、程序包导出与重载共用该格式。
- 接入 v35 的完整轴置换规范化；来源记录保留原图和坐标证明。
- 修正捕获策略、记录写入变量及 JSON 兼容类型处理。
- 默认来源仍为 v18，`latest` 仍为 v34；v36 通过显式版本选择。

线格式上限 4 MiB，还原工作量上限 16 MiB，最多 65,536 个容器节点、深度 64。通用图 JSON 的 32 MiB 上限是另一项限制。

## 真实后端结果

| 来源 | 计划 | 通过 | 失败 |
|---|---:|---:|---:|
| 未修改的历史真实 Agent DSL | 3 | 2 | 1 |
| 当前请求对应的既有规则 DSL | 1 | 1 | 0 |
| 人工等价符号修正 | 1 | 1 | 0 |

历史 Agent DSL 的两个通过项为前两行模型。32 维模型经过规范化后请求改变，旧代码使用的 `pv19` 已对应另一公开数组；旧值在新请求中对应 `pv27`。原代码完成编译和密态执行，但数值失败。仅改这一处符号后的人工程序通过，规则基线也通过；原 Agent 失败单列保留。

通过的四份程序对应三个数学模型，共 24 组密态输入、2,000 个输出值；最大绝对误差为 1.373751122857314e-6。门限保持 `1e-5 + 1e-4*abs(reference)`。独立审计同时复核了失败程序的 4 组输入、544 个输出值，审计通过表示记录正确，不表示失败程序通过。

来源扩展阶段共确认 5 次编译、9 次带完整记录的密态调用，其中一次数值失败。另一次早期重复执行在测试脚本时间窗口结束时中断，现场保留、不计通过。该窗口不影响已完成的模型数值验收；后续只续验未完成的复用检查。

## 使用

```bash
python3 scripts/prepare_pytorch_source.py --help
```

在现有导入命令中显式选择：

```text
--source-format poseidon-trusted-pytorch-v36
```

模型、权重和布局改变会产生新请求。程序包按完整来源、请求和依赖身份复用。
