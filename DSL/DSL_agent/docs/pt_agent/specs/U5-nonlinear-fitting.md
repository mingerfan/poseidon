# U5：非线性函数的自动拟合（remez、composite、newton），作为 Agent 和精调的新旋钮

PLAN §4.B 的 U5，排在 U4 之前。U4 中的 softmax 与 LayerNorm/RMSNorm 需要本轮提供的 `exp`、`inv`、`rsqrt` 近似。

本轮约束：
- 不调用 LLM；新增的代码、实验和测试不读取报告集（既有回归测试按 AGENTS.md 的例外执行）；
- 不修改编译器和运行时；不下载、不安装；
- **现有程序（只使用 `cheb`、`minimax_comp`、`exact`）发出的运算序列和数值逐字不变**；r8-v4/r8-v5 的提示词文本和精调行为不变。

## 0. 现状

- `act` 的 `fn` 已有 relu、silu、gelu、sigmoid、tanh、exp、inv、rsqrt、hardswish、square。方法只有：
  - `cheb`：Chebyshev 插值，接近最优；
  - `minimax_comp`：**只支持** DaCapo 自带的一组系数 `(15,15,27)`，读取自 `sgn151527.txt`；
  - `exact`：只在 square 时可以 lowering。
- maxpool 的近似参数同样只允许 `cheb` 和 `minimax_comp`。
- `inv`、`rsqrt` 在任何定义域上都只能用 Chebyshev 硬拟合，没有迭代法；`exp` 也只有 Chebyshev。
- 精调（`planners/tuner.py`）只沿 `LADDER=(255,127,63,31,15,7)` 降低 `cheb` 的阶数，不处理其他方法，也不会切换方法。

## 1. 新方法（新增 `kernels/approx.py`；原有 `kernels/poly.py` 的函数行为不变）

所有系数都在 lowering 时由可信库**确定性地**生成：只用 numpy，固定迭代次数和停止判据，不依赖随机数，每次运行得到逐位相同的系数。同一组参数的结果按参数缓存。

### 1.1 `remez`：任意函数的单段最优多项式

- 参数：`fn`、`deg`、`domain=(lo, hi)`。
- 算法：在映射到 [-1,1] 的区间上做 Remez 交换。初始参考点取 Chebyshev 极值点；每轮在 deg+2 个参考点上解线性方程，求出系数和等振荡误差 E；然后在密网格（不少于 `64·(deg+1)` 个点，含端点）上找到新的极值点，替换参考点。
  - 收敛判据：`(max|err| − |E|) / |E| ≤ 1e-6`，最多 50 轮。不收敛就报错，**不能悄悄退回 cheb**。
  - 对 relu 这类非光滑函数，Remez 理论上仍然收敛，但较慢。如果 50 轮不收敛，就报错，并在报错中给出最后的 max|err| 和 E，供 Agent 改用其他方法。
- 输出 Chebyshev 基下的系数，求值**复用现有的 `cheb_eval`**（BSGS 方式），所以乘法深度与同阶数的 `cheb` 相同。
- 性质：同一 fn、deg、domain 下，remez 的最大误差不大于 cheb 插值；等阶数下更准，等精度下可以用更低的阶数。

### 1.2 `composite`：组合 sign 多项式（用于 relu 与 maxpool 内部的 relu）

- 参数：`degrees=(d1, d2, …, dk)`（每个都是奇数）、`domain=(-B, B)`，以及 `eps`：sign 的过渡区宽度，即在 |t| ≥ eps 的区间上要求逼近 ±1，其中 t = x/B。
- 语义与现有的 `minimax_comp` 相同：`t = x/B`，`s = p_k(…p_1(t))` 近似 sign(t)/2，`relu(x) = x·(s + 0.5)`。
- 生成算法（Lee et al. 2021 的组合 minimax 思路，按奇函数做 Remez）：
  - 第 1 段在 [eps, 1] 上求奇多项式（基为 t, t³, …）对常数 1 的最优逼近；
  - 第 i 段的输入区间是上一段输出值的范围 [1 − E_{i−1}, 1 + E_{i−1}]，在这个区间上同样求奇多项式对 1 的最优逼近；
  - 最后把输出缩放到 ±1/2。
  - 收敛判据和最大轮数与 1.1 相同。
- **正确性锚点**：取 `degrees=(15,15,27)` 和与 DaCapo 系数相当的 eps，在 [eps, 1] 上的最大误差**不大于** DaCapo 自带系数（`minimax_coeffs((15,15,27))`）的误差。用 2^16 个点的密网格评估，汇报两者的误差。如果做不到，停下来汇报。
- 阶数拆分的自动搜索：给定"总乘法深度上限"和 eps，枚举奇数阶数元组（每段 ≤ 63，段数 ≤ 4），选出满足"最大误差 ≤ 目标"的、乘法深度最小的元组；深度相同时取总运算数较小的。结果缓存。这个功能以函数接口提供，供规则规划器和精调调用。PT-DSL 中仍然写明具体的 `degrees` 和 `eps`。
- 现有的 `minimax_comp` **保留不变**，仍然使用 DaCapo 的固定系数，冻结程序继续依赖它。

### 1.3 `newton`：倒数与倒数平方根的迭代法

- 只用于 `fn ∈ {inv, rsqrt}`，`domain=(lo, hi)`，要求 0 < lo < hi。
- 参数：`deg0`（初值多项式的阶数）、`iters`（迭代次数）。
- 计算过程：
  - 初值 `y0 = remez(fn, deg0, domain)(x)`；
  - inv 的迭代：`y ← y·(2 − x·y)`；
  - rsqrt 的迭代：`y ← y·(3 − x·y²)/2`。
  - 运算顺序是固定的（例如 rsqrt 为 `t = y*y; t = x*t; t = 3 - t; y = y*t; y = y*0.5`，与张量引擎完全一致），以保证 Mock 与张量引擎逐位相同。
- 乘法深度：inv 每次迭代 2 层，rsqrt 每次迭代 3 层（常数乘法按现有 kernel 的规则计入）。在汇报中，按 deg0 和 iters 给出深度与最大相对误差的表。

### 1.4 适用范围

| 方法 | 适用的 fn | 用于 maxpool |
|---|---|---|
| cheb（现有） | 全部 | 是 |
| remez | 全部（relu、hardswish 等非光滑函数允许，但可能不收敛并报错） | 是 |
| minimax_comp（现有，固定系数） | relu | 是 |
| composite | relu | 是 |
| newton | inv、rsqrt | 否 |
| exact | square | 否 |

不适用的组合在 typecheck 阶段报错，并说明可用的方法。

## 6. 修订 §1.3：rsqrt 的运算顺序与深度（Claude 于 2026-10-26）

**现象**：按 §1.3 的固定顺序 `t = y*y; t = x*t; t = 3 - t; y = y*t; y = y*0.5`，Count 后端计为每轮 4 层（3 次密文乘法，加上末尾乘常数 0.5 也消耗 1 层）。实测 1/2/3 轮分别为 4/8/12 层，与 spec 写的 3/6/9 层矛盾。

**决定：改用每轮 3 层的顺序**，把常数因子提到循环外面，深度计数规则不变（乘常数仍计 1 层）：

```
x_half = x * 0.5                 # 迭代开始前计算一次
重复 iters 次：
    t = y * y
    t = x_half * t
    t = 1.5 - t                  # 加减常数，不消耗层
    y = y * t
```

- 数学上等价于 `y ← y·(3 − x·y²)/2`。
- **深度**：`depth(rsqrt) = max(depth(y0), depth(x_half)) + 3·iters`。因为 `deg0 ≥ 1` 时 `depth(y0) ≥ 1 = depth(x_half)`，所以等于 `depth(y0) + 3·iters`。x_half 与初值多项式并行计算，不增加关键路径。
- **inv 的顺序**保持 §1.3 的写法，明确为 `t = x * y; t = 2 - t; y = y * t`，每轮 2 层，`depth(inv) = depth(y0) + 2·iters`。
- Mock、张量引擎、P2 包都使用完全相同的顺序，包括 x_half 的计算位置，以保证逐位相同。
- §3.2 的 newton 深度/误差表和 §3.3 的深度测试，按上面的公式校验：Count 统计的乘法深度必须等于公式值。

其余条款不变，请继续实现。

## 7. 修订 §1.1、§1.2、§3.2：Remez 判据的浮点下限（Claude 于 2026-10-26）

**现象**：SiLU、domain=(−8,8)、deg=63，50 轮后 `max|err| = 4.1525005656239955e-11`、`|E| = 4.1521867646461444e-11`，相对差 7.56e-5，超过 1e-6。7、15、31 阶都通过。

**判定**：这不是算法错误，而是**达到了 float64 的分辨极限**。
- 两者的绝对差约为 3.1e-15。SiLU 在该定义域上 `max|f| ≈ 8`，`ε_64·max|f| ≈ 1.8e-15`（ε_64 = 2^−52 ≈ 2.22e-16）。差值只有约 1.7 倍的 `ε_64·max|f|`，已经低于在密网格上计算误差时的舍入噪声。
- 当 |E| 本身很小时，`1e-6·|E|` 远低于 float64 能够分辨的量级，原判据不可能满足。

**修订判据**：
- 记 `M = max |f|`，在密网格上计算；composite 的各段中，M 取该段的目标值（1）与输入区间端点函数值的最大绝对值。
- 定义浮点下限 `τ = 64·ε_64·M`。

1. **§1.1、§1.2 的收敛判据**改为 `max|err| − |E| ≤ max(1e-6·|E|, τ)`，最多 50 轮不变。仍然不满足时照旧报错，**不回退 cheb**。
2. **§3.2 的等振荡检查**：deg+2 个交替极值的幅度与 |E| 之差 ≤ `max(1e-6·|E|, τ)`。
3. **§3.2 中"remez 的误差 ≤ cheb 的误差"**改为 `max|err_remez| ≤ max|err_cheb| + τ`。两者都已接近 τ 时，差别没有实际意义。
4. **汇报**：对每一组（fn、domain、deg），汇报 |E|、τ、实际的 `max|err| − |E|`，以及是哪一项判据生效（相对或下限）。下限生效的情况单独列出。这些情况下的近似误差已经接近机器精度，对精度毫无影响。
5. composite 的正确性锚点（与 DaCapo (15,15,27) 比较）按同样的 τ 口径比较：`max|err_ours| ≤ max|err_dacapo| + τ`。
6. newton 使用相对误差指标，不受影响。

不改变 Remez 算法本身，不引入高精度库。其余条款不变，从停止处继续实现与验收。

## 8. 修订 §1.2：composite 的基与搜索中不收敛候选的处理（Claude 于 2026-10-26）

**现象**：40 组平滑函数的拟合都通过；锚点 (15,15,27)、eps=2^−10 通过（误差 0.0031，DaCapo 为 0.0695）。自动搜索在 eps=0.2、目标误差 0.01 时，首段 degree=29 在 50 轮后：
- `max|err| = 0.0008555886503536225`
- `|E| = 0.000855584455932746`
- 差值 `4.19e-9`，大于允许量 `8.56e-10`（τ = 1.42e-14）。

**判定**：这不是 float64 的分辨极限（差值比 τ 大五个数量级），而是**基的条件数**问题。按奇幂基 t、t³、…、t^29 求解 Remez 线性方程组，在 29 阶时矩阵严重病态，求解误差限制了收敛，换算成 Chebyshev 系数时又会放大误差。

**修订 1：composite 各段改用奇数阶 Chebyshev 基求解**
- 奇多项式写成 `p(t) = Σ_{j=0}^{m} c_j · T_{2j+1}(t)`，其中 `2m+1 = 该段阶数`，t ∈ [−1,1]。奇函数的 Chebyshev 展开中只含奇数项，这是精确的表示，不是近似。
- Remez 的线性方程组直接以 `T_{2j+1}(t_i)` 为列，参考点 t_i 取在 [eps,1]（或该段的输入区间）上，交错误差项照旧。
- 列可以用三项递推或 `cos((2j+1)·arccos t)` 计算，两者要在测试中给出一致性证据。
- **不再从幂基换算**：求解结果直接就是 Chebyshev 系数（偶数阶系数为 0），交给现有的 `cheb_eval`。
- 收敛判据仍然是 §7 的 `max(1e-6·|E|, τ)`，最多 50 轮，不变。
- §1.1 的单段 remez 已经使用 Chebyshev 基，不受影响。如果它也有用幂基的路径，同样改为 Chebyshev 基。

**修订 2：自动搜索中不收敛候选的处理规则**
- **直接使用**（PT-DSL 中显式写出 `method="composite"` 和 `degrees`）：不收敛仍然报错，规则不变。
- **自动搜索**（§1.2 的阶数拆分枚举）：
  - 任何一段不收敛的候选元组，**排除**出可选集合，记入搜索日志（元组、段号、max|err|、|E|、差值），搜索继续；
  - 只有当所有候选都被排除时，搜索才报错，并汇报日志；
  - **不使用**不收敛候选的实测误差作为可行依据，所以最终选出的元组每一段都满足收敛判据。
- 汇报中统计每次搜索被排除的候选数。修订 1 生效之后，预计排除数为 0 或很少；如果仍然大量排除，停下来汇报。

**测试补充**：
- 原停止的那组（eps=0.2、目标 0.01、首段 29 阶）在新基下收敛；
- 锚点 (15,15,27) 的结果仍然通过，误差与修改前相比不变或更小；
- 一个人为构造的不收敛候选（把最大轮数临时设为 1），在搜索中被排除并记录，搜索仍然返回其他可行的元组；
- 直接使用的不收敛情况照旧报错。

其余条款不变，从停止处继续。
