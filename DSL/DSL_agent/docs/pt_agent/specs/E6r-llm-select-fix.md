## 2　修正（API 0，先做完并通过测试）

### 2.1　D1：精调调用的输出上限

精调 client 的 `max_tokens` 改为 `output_tokens('r8-v11')`（65536），与主循环相同；reasoning_effort 仍为 high。

### 2.2　D3：组合与冲突按字段判断

- 两步冲突的条件：它们的 `changes` 字段集合有交集。同一 softmax 的 exp、inv、step_inv、final_inv 角色步互不冲突，可以组合。
- 结构步与同一 op 的角色步可以组合，按以下方式构造：
  1. 先应用结构步，得到中间程序；
  2. 在中间程序上调用 `softmax_moves`，取该角色的近似步；
  3. LLM 选的角色步，其 `move['attrs']`（method、deg、deg0、iters、fit）若出现在第 2 步的结果中，就应用该结果；
     否则该候选记为 `not_legal_after_structural`。
  - 同一 op 上两个结构步，或同一 (op, 角色) 上两个角色步，仍算冲突，记为 `conflict`。
- 结构步与同一 op 的角色步之间按上面的方式组合，不再用字段交集判断（结构步会重建全部角色的定义域）。

### 2.3　D2：同一轮的候选是同一基准上的备选

每轮的流程改为：
1. 所有合法候选都在本轮开始时的程序（基准）上构造，依次做 `require_margin`、`program_failures`、代价估计（fast）。
   预测延迟不低于基准的记为 `cost`。
2. 剩下的候选按预测延迟从低到高验证（N_COARSE 粗验证 → `accept` → 全验证 → `accept`）。第一个通过的候选 A 被接受，
   当前程序更新为 A。
3. 合并：其余预测延迟低于基准、且与 A 不冲突的候选 B，按 B 的预测延迟从低到高，构造 A+B（规则同 §2.2），估计并验证；
   预测延迟低于当前程序并通过验证就接受，并更新当前程序。每轮最多 3 次合并尝试。
4. 本轮没有被处理到的候选记为 `not_reached`，同时记录原因（已有更优候选被接受，或预算用完）。不再使用 `stale`。

### 2.4　D4：停止条件

精调在以下任一情况时停止，然后执行 `finish()`：
- 连续两轮没有接受任何候选。截断或解析失败的轮次也算作没有接受。
- 已满 4 轮。
- 精调调用用满。
- 精调预算用完。

### 2.5　t1 提示词

在 t1 中说明：
- 组合规则（§2.2）。
- 同一轮的候选彼此是备选，系统接受其中预测延迟最低且精度通过的一个，再尝试与其余候选合并。
- 上一轮各候选的预测延迟和拒绝原因会随下一轮一起提供。

快照测试按新文本更新；E6 的 t1 文本另存为 `t1-e6`，供重现 E6 使用。

### 2.6　离线测试

- D1：精调 client 的 max_tokens 为 65536。
- D2：桩 LLM 给出 3 个同一点的备选，三者都被估计；接受预测延迟最低且通过验证的那个；其余记为 `not_reached`，
  不出现 `stale`。
- D2 合并：两个不冲突且都更低的候选，接受 A 后得到 A+B。
- D3：结构步加同 op 角色步，在合法时被组合，在中间程序上不合法时记为 `not_legal_after_structural`；同一 (op, 角色) 两步记
  `conflict`；不同角色的步可以组合。
- D4：一轮 length 之后继续下一轮；连续两轮无接受时停止；第 4 轮之后停止。
