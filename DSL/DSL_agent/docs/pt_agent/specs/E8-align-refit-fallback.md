# E8：精调定义域对齐的 refit 扩展与逐点回退（2026-11-08，接 E7）

## 0　背景

E7b 的两个 Qwen 会话（q1、q2）都没有冻结。确认阶段评估了 12 个候选，包括 LLM 的原始程序（41025、38560 自举），全部在原有的
校准 u 条件上被拒：第 32 行 rsqrt（`mul_13::rsqrt`）的校准 u 为 0.944–0.948，上限 0.90（`planners/agent_tools.py:30`）。
这些候选都没走到 E7 新增的尾部检查。E6r2-b Qwen p1 的失败原因相同。

**定义域的来源**：这个点的校准范围是 [888.3, 181205]。提示词给出的 `min_domain` 是校准范围放宽 1.5 倍（`margin.py:4`），
即 [592.2, 271807.6]，LLM 程序的上界基本照抄 271807.6。这个点的 u 按对数刻度计算：
- 在 [592.2, 271807.6] 上，校准最大值处 u≈0.87，到校准最大值的约 1.10 倍时 u 就到 0.90；
- 确认集有一个样本到 228.9k，是校准最大值的 1.26 倍，u≈0.944。

**精调器的对齐**：v8-6.24 的定义域对齐（`planners/transformer_tuner.py:433–498`）用 `margin_domain(lo, hi, factor=2)`
（`:70`）把这个点放到 [444.2, 362410.1]，上面那个样本的 u 降到约 0.86。按会话统计，对齐是否被接受与结果对应如下：

| 会话 | 对齐 接受/拒绝 | refit 状态 | 结果 |
|---|---|---|---|
| E5d BERT / Qwen | 3/0、6/0 | 全部 within | 7175、21857，均有效 |
| E6 s1 BERT / Qwen | 6/0、1/0 | 全部 within | 6808、22272，均有效 |
| E6r2-a BERT / Qwen | 3/0、6/0 | 全部 within | 与 E5d 相同 |
| E6r2-b BERT p1 / p2 | 4/1、1/2 | 有 closest | 7141、6977，均有效 |
| E6r2-b Qwen p1 | 0/2 | 一次全部 within，一次有 closest | 确认失败（第 32 行 rsqrt u 0.944） |
| E6r2-b Qwen p2 | 3/0 | 全部 within（LLM 写的上界已是 384000） | report 失败，E7 的 C1 会拒绝 |
| E7b q1 / q2 | 0/3、0/3 | 每次都有 closest | 确认失败（第 32 行 rsqrt u 0.946 / 0.944） |

**被拒的原因（已知部分）**：
- `refit`（`planners/margin_refit.py:69`）只在原方法内选设置，remez 和 newton 的阶数最高到 63 或当前阶数（`degrees`，`:53`）。
  q1、q2 的 LLM 程序本来就是 remez 63 阶，放宽后 7 个点都只能取 closest。例如：
  - 第 32 行 rsqrt：误差 0.0041，目标 0.0019；
  - 第 27 行 silu：误差 0.0141，目标 0.0036。
- E6r2-b Qwen p1 第一次精调的 7 个点都是 within，对齐仍被拒。对齐记录只有 `accepted`（`:490`），没有记录原因。

**被拒之后**：精调器从未对齐的程序继续下降（`:497–498`）。后续几轮 LLM 直接沿用上一轮精调后的程序（q1 第 3、4 轮的程序就是第 2、3 轮的
精调结果），于是池中所有候选都带着同一个窄定义域。

**本轮只改精调器**，新规则命名为 v8-6.25：
- **R0 对齐记录**：记录对齐被拒的具体条件（所有带对齐的规则都记录，不改决策）。
- **R1 refit 扩展**：原方法在 63 阶内达不到原精度时，先在原方法内升到 255 阶，再换同一函数的其他方法。
- **R2 逐点回退**：整体对齐被拒、且初始程序可行时，逐个点尝试放宽，保留通过的点。

接着做两部分：
- **E8a**：API 0，诊断、回归、会话回放；
- **E8b**：两个新的 Qwen 会话（用户已批准调用），E8a 满足 §4 的开始条件后开始。

不在本轮范围：提示词中 `min_domain` 的定义、u 上限 0.90、确认规则 c1/c2、`MAX_CONFIRM_EVALS`。E6 s1 BERT（6808）的 6 次对齐都在
stage 0 内被接受，v8-6.25 下应与原结果逐项相同，由 §3.3 核对。

### 2.2　R0：对齐记录（所有带对齐的规则，不改决策）

- **拆出判定项**：把 `accept`（`:403`）拆成返回未通过项列表的函数，`accept(result)` 等价于列表为空，决策不变。
- **domain 行新增字段**：
  - `metrics`：对齐后程序的测量结果，包括 feasible、diverged、agree、total、agreement_pct、logit_rel_err、`move_logit_limit`、

    - `alignment_error`：退化定义域；

    - `domain`：`criteria.domain_ok` 为假；
    - `accuracy`：`move_accuracy_ok` 为假；
    - `cost`：非 refit 规则下代价上升。
  
  接受时 `reasons` 为空。
- v8-6.24 的 domain 行也写入这两个字段。

### 2.3　R1：refit 扩展（只在 v8-6.25 下，`planners/margin_refit.py`）

**分阶段选设置**：按以下顺序进行，某一阶段出现 within 的设置就停止：

| 阶段 | 候选设置 |
|---|---|
| 0 | 与 v8-6.24 完全相同（`settings(attrs)`，`:59`） |
| 1 | 原方法，`LADDER` 中高于阶段 0 上限、且不超过 255 的阶数：remez 的 `deg`；newton 的 `deg0`，iters 取 0–5；cheb 在阶段 0 已到 255，无新增 |
| 2 | 同一函数的其他方法：inv/rsqrt 在 remez、newton 中换；其他函数在 remez、cheb 中换。阶数取 `LADDER` 中不超过 255 的全部值，newton 的 iters 取 0–5 |

**选择与记录**：
- 每个阶段内的选择沿用现有排序（depth，然后 deg/deg0，然后 iters）。阶段 2 再按方法名排序，保证结果确定。
- 三个阶段都没有 within 时，在全部可用设置中取 closest（误差最小，然后按上面的排序），状态记为 `closest`。
- 记录增加：所在阶段、选用的方法、各阶段的候选数和用时。

**换方法时的参数**：
- 参数按目标方法在 DSL 中的要求构造（`dsl/ops_spec.py:78 new_approx_error` 和类型检查）；
- remez 与 newton 互换时保留原 `fit`；换到 cheb 时去掉 cheb 不接受的参数；
- 构造不出合法参数的组合，以及数值失败的组合，都记为不可用（沿用现有的 try/except）。

**floor**：
- 只含数值参数 `deg`、`deg0`、`iters`，`method` 不进入 floor；
- 换了方法的点，其 floor 按新方法的数值参数记录。

**与 v8-6.24 的关系**：阶段 0 有 within 时，结果与 v8-6.24 逐项相同。

### 2.4　R2：逐点回退（只在 v8-6.25 下，`transformer_tuner.py:433–498`）

- **触发条件**：整体对齐（已含 R1）未被接受，并且初始程序可行（`repair_initial` 为假，`:432`）。初始程序不可行时，沿用 v8-6.24
  的处理。
- **顺序**：按 `points()` 的程序顺序逐个处理。跳过的点与整体对齐相同（softmax 点、没有校准测量的点），对齐后定义域不变的点也跳过。
- **每个点的处理**：
  1. 在当前累积程序上，只放宽这个点并按 R1 refit；
  2. 依次执行 `require_margin`、`program_failures`（a1）和 `measure`，引擎与整体对齐相同；
  3. 按 R0 判定，没有未通过项才接受。接受后，累积程序更新为这个候选，并记下这个点的 floor。
- **结束**：
  - 至少接受一个点时：当前程序取累积程序，代价只在最后算一次，floor 只含被接受的点；
  - 一个点都没接受时：与 v8-6.24 的拒绝路径相同（含 `:498` 的提前结束）。
- **记录**：domain 行增加 `fallback`。每个点记录：行号、role、fn、是否接受、`reasons`、`metrics`、refit 记录、用时；
  另记 `accepted_lines`。
- **计数**：逐点的测量计入 `full`，用时计入精调预算的墙钟，与其他评估相同。
