## 2　provider 故障处理（API 0，先做完并通过测试）

在 LLM client 外层（主循环和精调共用）实现：

- **可重试的错误**：HTTP 5xx、HTTP 429、连接错误或超时、status 200 但正文少于 100 字节的 invalid_response。
- **不重试**：其他 4xx、`finish_reason=length`，以及正文完整但内容无法解析的响应（这类按现有规则处理）。
- **重试方式**：等待 300 秒后重发同一请求，每个请求最多重试 2 次（共 3 次尝试）。每次尝试都写入账本、计入命名空间上限；
  请求文件不变，每次尝试的错误记录分别保存。
- **熔断**：跨会话连续 3 次尝试都是可重试错误时，停止整轮，记为 `provider_outage`，不再开始后面的部分；记录故障时间窗。
- **冷却**：任一会话以 provider 错误结束后，等待 600 秒再开始下一个会话。
- 不另发连通性探测请求。

离线测试（桩 client）：5xx 后重试并成功；短正文的 invalid_response 被识别为可重试；400 和 length 不重试；3 次连续可重试错误
触发熔断；每次尝试都计入上限，达到上限后不再重试；等待时间可在测试中注入为 0。E6r 和已有相关测试照常通过。
