# 24层 R121：结构、数据量、slot 与 level 分析

## 口径

本文件只描述 `Qwen25_24Layer_R121_DSL`。结构和原始权重数量可由24层schema精确计算；当前未生成该版真实尺寸编译计划，因此编译后明文/密文总数、level分布、自举次数、全保留系数总量、运行峰值内存和耗时均为**待测**，不拿两层数据乘12冒充实测。

机器可读结果在 `evidence/structural-analysis.json`。本包是对应Qwen2.5 0.5B结构的DSL实现，使用合成权重验算，不包含预训练权重和质量评测。

## 原始权重与数据量

| 项目 | 精确数量 |
|---|---:|
| 每个Block参数元素 | 14,912,384 |
| 24个Block参数元素 | 357,897,216 |
| embedding元素 | 136,134,656 |
| LM head元素 | 136,134,656 |
| 最终RMSNorm元素 | 896 |
| 291个独立数组合计元素 | 630,167,424 |
| 当前独立embedding/LM head，float32原始payload | 2,520,669,696 bytes，约2.348GiB |
| 如果embedding/LM head共享，同一权重只计一次 | 494,032,768元素；float32为1,976,131,072 bytes，约1.840GiB |

当前合成生成器分别存储embedding和LM head；共享那行只是schema层面的唯一参数计数，未实施存储共享优化。共享参数的float16/bfloat16原始payload约0.920GiB，能解释“0.5B权重约1GB”的说法。上述数字都不包含编码扩张，也不是CKKS工作内存。

加密计算直接输入embedding向量；embedding表不必完整编码进入同态计算图。LM head及各层线性权重会通过所选打包方式展开成明文常量，实际常量数、复制次数、level和Encode次数要看编译计划。即使原始权重共享，embedding查表与LM head同态运算的表示也不同。

## 输入输出与slot占用

每密文32768槽。以下是特定表示的有效数据占比，不是整个模型的平均槽利用率，也不是所有明文权重的利用率。

| 表示 | 有效槽/密文 | 比例 |
|---|---:|---:|
| 单token embedding / hidden前缀 | 896 / 32768 | 2.734375% |
| 两token并列hidden有效元素 | 1792 / 32768 | 5.468750% |
| 单token MLP中间向量前缀 | 4864 / 32768 | 14.843750% |
| 两token配对MLP两区 | 9728 / 32768 | 29.687500% |
| 两token每层持久KV | 512 / 32768 | 1.562500% |
| 单token每层持久KV | 256 / 32768 | 0.781250% |
| logits全部5块合计 | 151936 / 163840 | 92.734375% |

临时重复、旋转和归约产生的槽布局可能更密集；多个复制槽不等于更多独立模型元素。跨层KV仍独立存放，没有实现24层KV共享一个密文。

默认2个输入密文含1792个有效实数；所有输出为5个logits密文+24个KV密文，共29个。24层KV共12288个实数，原始float64参考为98304bytes；全部输出有效实数164224个，float64参考为1313792bytes。展开到完整29×32768个float64槽的参考数组约7.25MiB，这依然不是密文存储大小。

## 自举和level

CPU参考编译合约的自动自举输入L1、输出L5，scale43；权重、mask、偏置等明文应编码到实际消费者需要的level。rescale、modswitch和Bootstrap由匹配编译器安排，模型Python源码没有逐层硬编码完整level表。

这次扩展后，前23个Block走两token配对MLP，末层保持既有末层路径。编译器还可裁剪不影响最终logits/KV的分支。新的跨层依赖、自举边界和缓存返回level都需要重新编译分析；因此不能说每层执行固定次数自举，也不能用两层74次乘12。

以环度65536、64-bit RNS系数为例，一个明文Q部分约为 `65536 × 活跃模数个数 × 8 bytes`；二分量密文约为其两倍。若当前后端level L对应L+1个Q模数，则L1分别约1/2MiB（明文/二分量密文），L5约3/6MiB。实际统计应读计划元数据和后端约定；扩展P模数、三分量乘积、密钥和自举工作区另计。

## 内存优化实际包含什么

算子侧沿用R121的QKV tile128、配对MLP down tile256、宽矩阵和LM head打包；CPU计划侧保留终端刷新消除、release_ready释放调度及64MiB Encode根缓存。源码策略已经交付，但其在24层上的完整性能收益还没有测得。计划系数之和不含密钥、allocator、bootstrap内部工作区，不等于进程RSS；开启释放也不能把这些额外开销算成零。

父版两层R121实测74次自举、2740.815秒、27.079472GiB RSS；其静态全保留系数141.609375GiB。这里仅提供出处，不作为24层结果或预测。

## 已完成验证及剩余验证

两组缩小宽度的24层计算各跑了4条路径，含独立权重和所有24个缓存。basic使用32槽、hidden8/intermediate16；tiled使用1024槽、hidden8/intermediate385，真正覆盖了tile256及第二块列切片。两组都与独立sqrt、sigmoid/SiLU、Softmax dense参考比较，容差1e-5；最大误差约8.98e-8。输入尾部非零，输出尾部检查为零，外部KV未被修改。

这验证源码组合和小尺寸算术，不验证真实宽度编译、密文噪声累积、自举精度、原模型语言质量或GPU执行。下一步在目标服务器生成真实尺寸权重/图，编译并用PlanVerifier与Mock验收，再决定完整CKKS/GPU测试。CPU与GPU均应保留对应版本的level、内存和精度报告。
