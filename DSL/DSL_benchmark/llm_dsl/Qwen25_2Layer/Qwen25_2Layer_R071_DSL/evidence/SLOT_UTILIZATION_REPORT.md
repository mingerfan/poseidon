# 当前两层模型的槽位布局审计

对应071已通过CKKS的060 DSL，两层、两token顺序decode、合成权重。源码清单哈希与冻结版本一致；本次仅静态尺寸计算，没有重跑模型。

每个密文有32768个复数槽位，当前模型在实部承载实数。以下有效数据计数按逻辑坐标定义，不按数值是否恰好为零定义，也不把CKKS噪声算成有效数据。

## Linear乘法阶段的布局

把输入复制到多行区域，与不同权重行相乘，然后归约、收集输出。输入副本虽重复，但与不同权重相乘完成不同点积，属于有效并行工作。以下只统计这种权重乘法布局，不能当作整个Linear所有指令的平均利用率。

## RMSNorm与Attention内部

- RMSNorm输出为896维，即2.734375%；归约后同一个均方标量广播到全部32768槽，再做逆平方根多项式。此时布局覆盖100%，但独立标量仅1个，不能称处理了32768份不同数据。
- 两可见token的Attention使用pair13专用路径：每个查询头算一个中心化分数，共14个独立分数（0.042725%），之后每个分数复制64次，与对应V坐标逐元素组合，相关区域896槽（2.734375%）。
- 这条路径隐式实现两项Softmax概率组合，不另外保存一张2×14概率矩阵；不可把通用多token实现的布局套到当前分支。只有1个可见token时概率恒为1，直接走V展开，跳过Softmax多项式。
- 多项式常量、归约残留和循环移位可能使其他槽位在某些中间步骤也非零。非零不等于承载额外独立有效数据。
- 两层接口布局相同不代表每个子层执行次数相同：编译器会裁掉不影响最终logits和KV的路径。此表不是全图各指令统计。

## LM head与最终输出

LM head输出151936维，使用5个密文，平均有效比例92.734375%。前4个为100%，最后20864槽为63.671875%。
LM head内部把896维输入按1024周期复制，输入覆盖87.5%；完整输出块的对角权重有效比例在全部对角线平均为87.5%。输出100%与内部87.5%是不同口径。

每层最终KV把2token×2(K/V)×2KV头×64维合在一个密文，共512槽，1.5625%；改善了对象数量，但短序列时仍明显稀疏。

## 如何解释

当前主要的低占用位置是隐藏向量、Attention分数和短KV缓存；不能因层输出只有2.73%就说Linear乘法也只有2.73%。反过来，不能用复制填满槽位来声称独立数据利用率已经100%。
这里未给全模型统一平均值：它需要明确按指令、存活时长还是level加权，并统计每个中间值的布局。静态接口比例不能直接换算成等比例内存或时间节省。
用户要求暂停下一轮优化，本次只生成布局分析；没有改动模型、打包方式或启动测试。
