## 已执行什么

在 V100 32 GiB 单卡上，用两套独立非零随机秘密密钥（h=192，96 正/96 负），
每轮 32768 个实数槽，正常公钥加密，连续执行：

```text
Q6 / scale40 输入
 → S2C: Q6→Q5→Q4→Q2
 → 整数3897准备: Q2 / scale58.97349886989023
 → ModRaise: Q2→Q50
 → C2S: Q50→Q49→Q48→Q46
 → degree59 / DA2 / arcsine_degree=0 的 EvalMod 与既定系数折叠
 → Q31 / scale40 输出
```

这次入口预留了把此输出直接交给 ReLU 的连续路径，但两轮都在首次自举后检测到
数量级错误而停止，**没有执行后续 ReLU、卷积、完整网络或分类准确率评估**。
输入在 Q6 直接加密，不冒充已经跑过网络前半段。所有中间检查只下载/解密副本，
没有把明文参考或解密结果重新加密插回计算链。

## 定位：C2S 输入归一化破坏了 EvalMod 的整数周期

升模后，在系数域中通常存在 `message * Δ + k * Q0`。这里 `Q0` 表示保留的
两个底层素数的乘积，不是单个素数；`k` 是应由 EvalMod 消去的整数项。
升模结果此时不应该直接与原消息做恒等比较。

当前 witness 的实际数值为：

| 参数 | 数值 |
|---|---:|
| Q0 = q[0] × q[1] | 18108846910416224257 |
| q_diff = Q0 / 2^64 | 0.9816825580740343 |
| 准备后的 log2(Δ) | 58.97349886989023 |
| 传给 C2S 的逻辑 log2(scale) | 44.97349886989022 |
| 增加一个 k 时，EvalMod 输入的步长 | 0.04074155739499797 |
| EvalMod 正弦映射要求的周期 | 0.04 |
| 一个整数项实际对应的周期数 | **1.0185389348749492** |

偏移约 **1.854%**。因此，本来应当无影响的整数倍模数项，经过正弦映射后没有
消失，而成为很大的输出错误。这一接口是当前已定位的首个重大语义错误：
**ModRaise 之后的逻辑 scale 校准与 C2S/EvalMod 系数没有联合满足整数周期条件。**

独立数值反例（不是零秘密密钥测试，也不是新一轮 HE 测试）：

- 消息 m=0、整数项 k=0：当前 degree59 多项式输出约 1.29e-8。
- 同一消息 m=0、整数项 k=1：输出变成约 **0.58106305**，而正确自举仍应接近 0。

`audit_bootstrap_period.py` 使用保存的实际素数和原多项式系数复现这个反例。
原静态 `verify_joint.py` 仍然返回 `PASS_SCALE_LEDGER`，而新增周期审计返回
`period_alignment_pass=false`。**之前的验证缺口就在于只验证了 Q/scale 和系数
折叠，没有验证非零秘密密钥下的升模周期语义。**

## 为什么不是 GPU 算错或单纯拟合不够精确

第 1 轮的主要对照：

| 对照 | 最大误差 | 含义 |
|---|---:|---|
| 纯明文 S2C/C2S 逆变换 | 1.28e-15 | 矩阵方向及归一化的参考实现相互一致 |
| S2C 最后一阶段相对其输入的明文矩阵运算 | 6.84e-9 | 本阶段额外计算误差较小 |
| 整数准备前后解密结果 | 4.55e-13 | ×3897 并同步更新 scale 保持值 |
| C2S 全三阶段相对升模输入的明文矩阵运算 | 7.49e-9 | 基本正确执行了所指定的矩阵 |
| degree59 明文多项式相对理想正弦映射 | 5.18e-6 | 拟合误差不是 6.97 大错误的来源 |
| 理想正弦映射相对原始输入 | **6.96581997** | 即使把多项式替换为精确正弦，依然错误 |
| GPU 最终输出相对 degree59 明文结果 | 1.58e-5 | GPU 与当前指定函数基本一致，但指定函数不恢复原值 |

以上参照对象、表示域不同，不能把各行的最大误差直接相加，也不能把原始 C2S
各中间阶段不同量级的值当作应用激活值。日志中的 `max_imag` 是解密值的虚部
幅度，不是对照误差；变换域出现非零虚部正常，最终恢复实数输入仍应接近实数。

## 后续应修什么；目前没有宣称修好了

1. 先把 **整数周期** 对齐，再联合补偿消息幅值；不是仅覆盖一个 scale 标签。
   数值反事实中，把 C2S 逻辑 scale 设为 2^45 可使周期数变成 1，但消息的一阶
   幅值增益还约为 0.9817985，仍需相应系数补偿。这只是定位用的计算，尚未实密文
   验证、没有作为生产修复提交。
2. 联合重跑 Q/scale 账本与单次自举实测。**这次失败没有证明 Q50 数量本身不足**，
   证明的是当前定标组合错误。
3. 即使周期修复，还需测 `arcsine_degree=0` 的正弦替代恒等映射误差。当前数值
   对照中，k=0、m=0.5 仍有约 8.33e-4 的误差；这与上述整数周期大错误是两回事。
   不能仅凭名称“59 阶高精度”认定整个自举误差足够小。
4. 单次自举通过后，将真实输出连续接入 ReLU、真实 ConvBN，再测试多轮和完整
   ResNet20，并沿途记录首次明显偏离的位置、最终 logits 和预测类别。
