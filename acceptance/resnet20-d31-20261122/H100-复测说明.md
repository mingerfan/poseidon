# H100 复测入口

当前没有 H100 实机，任何 A800 测量都不能写成 H100 测量。实验队列结束后，A800 的独立目录 `/root/resnet20-d31-perf-20261120.4aP2lX` 会尝试从已通过完整密文回归的候选中选择 A800 在线中位数最低者，记录在 `h100-selected.json`，并以 `CMAKE_CUDA_ARCHITECTURES=90` 交叉编译。跨机器使用前，应在 H100 环境用对应源码快照和本机依赖重新构建；A800 的二进制可能依赖其本机库。

成功构建后，该目录中的 `h100-test.sh`、`h100-selected-flags.env` 和 `h100-selected.json` 可连同对应源码快照一起复制。脚本默认使用同目录下的 `h100-source`、`h100-build`，也可分别通过 `POSEIDON_H100_SOURCE` 和 `POSEIDON_H100_BUILD` 指向 H100 本机的源码和构建目录。源码中的 `trident-functional/resnet20/functional_params` 必须完整保留。构建时按仓库依赖配置使用 `-DCMAKE_CUDA_ARCHITECTURES=90`，构建目标包括 `resnet20_wide_functional`、`functional_wide_ntt_probe` 和 `functional_wide_bv_probe`。

```bash
CUDA_VISIBLE_DEVICES=0 ./h100-test.sh base 0
CUDA_VISIBLE_DEVICES=0 ./h100-test.sh best 0
```

`base` 启用 OPT-002、OPT-007、OPT-008 的公共开关；`best` 再启用所选候选的开关。两者使用同一构建，建议交错重复至少五次，再比较在线时间、GPU 活动及显存采样。每次生成独立日志目录，先运行 NTT 和 BV 组件探针，再执行指定图像的完整网络；`memory.csv` 带 GPU index 和 UUID，应按实际设备确认峰值显存。`POSEIDON_WIDE_POOL_GIB` 默认 60，可根据设备资源明确调整并在报告中记录。

交叉编译成功只说明编译通过，不等于 H100 正确性、性能或密码学安全性已验证。H100 实机验证需检查逐样本结果、原始日志和测量口径；安全状态在独立评估前仍为 `SECURITY_NOT_VALIDATED`。

脚本的参数、日志目录和探针调用已用不访问 GPU 的模拟程序做过冒烟检查；模拟输出不属于硬件测试结果。交叉编译与 H100 实机运行仍以实际日志为准。
