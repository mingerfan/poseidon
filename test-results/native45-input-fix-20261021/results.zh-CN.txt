修改
1. native Boot 与普通计算使用同一设备计算流，并显式选择 CUDA device。
   原先 Boot 在 PTDS 提交，普通运算在 foreground stream 提交，会并发使用 Evaluator 的 Rescale 等工作区。
   输入保留会改变出错概率，但仅延长输入存活期不是修复。流修复单独消除了批量测试中的14个大误差输出。
2. 在 ModRaise 前执行高精度归一化。以下 scale 都是实际比例，非 log2 值：
   ModSwitch 到 q0 上方一个 Q；k = round(T * q_last / input_scale)；
   先乘整数 k，实际 scale 同时乘 k；再 Rescale 一次到 q0，scale 除以真实 q_last。
   T 为 profile 的 q0_over_message_ratio。保留计算得到的实际 scale，不直接覆盖为 T。
   k 必须在 [1, 2^53]，需要 q0 上方至少一个 Q，否则直接报错。
   原先 scale50.3477 时只乘 round(T/input_scale)=25，约0.58%的比例误差进入 Boot。
   原先高 scale 输入先降 scale 再放大；现在把乘法放在 Rescale 前，保持输入精度。
3. builder 的最小输入 level 从 q0_level 改为 q0_level+1（当前为2）。
   active OperatorSpec 仍使用更保守的输入下界4，无需修改 profile JSON。
   用于归一化的 Q 原本会在降到 q0 时丢弃；恢复后仍是 level22、scale45、2个分量。
   工作下界4，Boot 恢复后可用预算仍为18个 Q。
